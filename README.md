# Единый каталог запасных частей NHL — самосвалы с ДВС

Самодостаточный веб-каталог запчастей по **всему парку самосвалов NHL**:

| Машина | Тип | Двигатель |
|--------|-----|-----------|
| **NTE240** | электромеханический самосвал | Cummins QSK60 |
| **NTE200** | электромеханический самосвал | — |
| **TR100A** | механический самосвал | Cummins QST30 |

Ветка `main` содержит только сам сайт (корень репозитория = корень сайта) и
предназначена для публикации на **Vercel** без сборки — всё работает как
статические файлы и открывается даже из `file://`.

## Как устроено

Приложение открывается **экраном «Выбор моделей»**: карточки трёх машин, у
каждой — разделы **Машина**, **Электропривод** и **Двигатель**. Кнопка
**«⌂ Выбор моделей»** в шапке (и «хлебные крошки» в разделах) в любой момент
возвращает к этому экрану.

Внутри машины сверху бокового меню — переключатель разделов:

- **Машина** — узлы самосвала (рама, гидравлика, ходовая, кабина, тормоза и т. д.).
- **Электропривод** — тяговый электропривод (глава 600); есть только у
  электромеханических NTE240 и NTE200.
- **Двигатель** — единый **каталог EPC Cummins** (выгрузка с parts.cummins.com),
  лежит в подпапке `cummins/` и открывается встроенным окном на нужном двигателе
  по серийному номеру (ESN):
  - NTE240 — Cummins **QSK60 CM2150** (ESN 33239746);
  - NTE200 — Cummins **QSK50 CM2150** (ESN 33239899);
  - TR100A — Cummins **QST30 CM552** (ESN 37295879).
  Каталог `cummins/` — фото деталей, характеристики, цепочки замен номеров,
  ремкомплекты; переключатель ESN открывает нужный двигатель (`?esn=<ESN>`).
  Прежние варианты «из PDF» в раздел «Двигатель» не выводятся.

  Вместе с каталогом двигателя лежит **база знаний Cummins** (кнопка «База
  знаний» в его шапке) — выборка из QuickServe ровно по этим трём двигателям
  и трём машинам: см. раздел «База знаний Cummins» ниже.

В шапке также **переключатель машин** и общие инструменты сразу по всему
оборудованию:

- **Переключатель NTE240 / NTE200 / TR100A** — мгновенно меняет каталог,
  боковое меню и чертежи выбранной машины.
- **Поиск** — по номеру детали или названию в каталоге текущей машины. В шапке
  раздела рядом со ссылкой на полный каталог машины стоит **«📘 Инструкция по
  ремонту»** этого узла, если она есть.
- **📚 Полный каталог машины** и ссылка в каждом разделе (**«Открыть раздел в
  полном каталоге машины»**) — переход в родной каталог машины с
  **руководствами по эксплуатации, инструкциями по ремонту и каталогом
  двигателя**. Родные каталоги лежат в подпапках `nte240/`, `nte200/`, `tr100/`.
  У NTE240 это руководство оператора, 70 инструкций по ремонту по разделам
  каталога и заводские руководства по сборке и сварке в PDF (см.
  «Документы машин» ниже).
- **⬇ Экспорт всех номеров по всему оборудованию (Excel)** — выгрузка всех
  каталожных артикулов по трём машинам сразу (с колонкой «Машина», ценами,
  наименованиями и разделами).
- **🔎 Проверить список** — проверка списка номеров **по всем трём каталогам**:
  - какие номера из списка **есть в каталоге** и в какой машине/разделе
    (в т. ч. по взаимозаменяемому — старому — артикулу);
  - номера, которых нет в каталоге машины, но которые есть в **каталоге
    двигателя** Cummins (933 из 2692 позиций EPC) — со статусом «найдено
    (каталог двигателя)», узлами EPC и кнопкой, открывающей деталь в каталоге
    двигателя;
  - какие номера из списка **отсутствуют в каталоге**;
  - какие номера каталога **отсутствуют в вашем списке** (кнопка
    «⬇ Отсутствуют в списке»).
  - для номеров двигателя — **«Не поставляется отдельно»** (в каталоге EPC
    деталь помечена `Sellable: N`, то есть отдельной позицией её не продают)
    и рядом **«Входит в комплект»** — номера и названия ремкомплектов, которыми
    такую деталь можно заказать;
  - **«База знаний»** — вся остальная информация по номеру: сервисные
    бюллетени, TSB и процедуры QuickServe, где он упоминается (ссылки
    открывают документ), и инструкции по ремонту тех узлов машины, где деталь
    стоит. В выгрузке это столбцы **«Документы базы знаний»** и
    **«Инструкции по ремонту»**.
  Все эти поля есть и в таблице на экране, и в выгрузке Excel (в т. ч.
  в «Отсутствуют в списке»).
  - Результат выгружается в Excel.
- **Заказ-спецификация** — корзина с количеством, ценами и экспортом/печатью;
  поддерживает позиции сразу нескольких машин (с колонкой «Машина»).
- **💲 Обновить цены** — загрузка прайса (`.xlsx`/`.csv`) для выбранной машины,
  цены сохраняются в браузере; можно скачать `prices.js` для постоянного
  обновления в подпапке соответствующей машины.

## База знаний Cummins

В каталоге двигателя (`cummins/`) рядом с составом узлов лежит **база знаний**:
документация QuickServe и книги машин со сквозными перекрёстными ссылками —
из процедуры в деталь, из детали в узел и обратно в документы, где она
упоминается. Переключение — кнопками **«Каталог / База знаний / Документы /
Машины / Детали»** в шапке каталога двигателя, адреса вида `#/doc/<номер>`.

Выборка сделана **ровно по трём двигателям и трём машинам NHL**; всё, что
относится к другой технике, в неё не попадает.

| Что | Сколько |
|---|---|
| Документы QuickServe | 1733 (процедуры 1393, TSB 243, бюллетени 38, инструкции по инструменту 36, руководства 17, инструкции по установке 5, габаритные чертежи 1) |
| Руководства (по разделам, с оглавлением) | 17 |
| Детали Cummins с русскими наименованиями | 2939 |
| Детали машин NTE240 / NTE200 / TR100A | 6650 |
| Тем-подборок | 12 |

Что можно делать:

- искать сразу по документам, деталям Cummins и деталям машин (поиск в шапке
  работает и в базе знаний);
- читать процедуры ремонта и TSB **по-русски** — переключатель `RU / EN`
  в шапке; тексты выгружены на обоих языках, рисунки процедур лежат локально;
- открывать разделы книг машин с чертежами и составом, а также инструкции по
  ремонту и руководства (PDF) прямо из базы;
- из карточки детали в каталоге переходить в базу знаний и обратно в узел.

### Документы машин

Руководства и инструкции по ремонту машина хранит у себя (`nte240/`, `nte200/`,
`tr100/`), а база знаний берёт их оттуда — второй копии нет. По NTE240:

| Документ | Где в каталоге | Собран из |
|---|---|---|
| Руководство оператора (26 разделов, 143 иллюстрации) | `nte240/manual.html` | `NTE240 Driver's Manual-Polyus.docx` |
| Инструкции по ремонту и обслуживанию — 70 разделов | `nte240/service/` | перевод заводского руководства по ремонту 2023 г. |
| Руководство по сборке (47 с.) и инструкция по сварке кузова (30 с.) | `nte240/manuals/` | PDF завода |

Сборка (нужен LibreOffice, исходники — в ветке `rawdata`):

```
python3 build/gen_nte240_manual.py  "NTE240 Driver's Manual-Polyus.docx"
python3 build/gen_nte240_service.py <папка с главами руководства по ремонту>
python3 build/gen_service_tables.py <та же папка>   # текст -> настоящие таблицы
```

`gen_service_tables.py` возвращает в инструкции по ремонту **настоящие
таблицы**: спецификации к рисункам, моменты затяжки, перевод единиц, массы
узлов, таблицы поиска неисправностей. Структура берётся из исходных файлов
Word, текст — со страницы каталога; совпадение проверяется посимвольно, так
что текст не может измениться, меняется только разметка. 110 таблиц собрано по
исходнику и ещё 21 спецификация — запасным разбором «номер позиции /
наименование».

После этих скриптов `node build/gen_kb.js …` подтянет свежие названия разделов,
новые инструкции и список PDF на страницу машины в базе знаний, а
`node build/gen_part_docs.js` — ссылки на инструкции в «Проверить список».

### Как это собрано

Источник — репозиторий **Cummins_Parts_Book** (выгрузка QuickServe). Перенос
и фильтрация — скриптом:

```
node build/gen_kb.js /путь/к/Cummins_Parts_Book
```

Скрипт кладёт в `cummins/`: индексы `data/kb_*.js`, тексты документов кусками
`data/kb/body*.js`, книги машин `data/kb/machine_*.js`, рисунки процедур
`assets/figures/` и PDF документов `bulletins/<категория>/`.

Ничего не дублируется: чертежи и руководства машин база берёт из уже
имеющихся `nte240/`, `nte200/`, `tr100/`, фотографии деталей — из
`cummins/photos/`; пути к ним скрипт переписывает прямо в данных.

PDF процедур (~650 МБ) в репозиторий **не переносятся** — их полный текст с
рисунками и так лежит в базе; PDF берутся для TSB, бюллетеней, руководств,
инструкций и для тех редких процедур, текст которых не выгрузился.

## Структура

```
index.html, app.js, styles.css, unified.css, gate.js   — единое приложение
data/catalogs.js   — window.MACHINES + window.CATALOGS (три каталога, пути к
                     чертежам уже с префиксом машины)
data/prices.js     — window.PRICES_BY (цены по машинам)
data/engine_sup.js — замены номеров двигателя (старый → действующий)
data/engine_parts.js — комплектность номеров двигателя: не поставляется
                     отдельно / входит в комплект (для «Проверить список»)
data/part_docs.js  — что ещё известно про номер: документы базы знаний,
                     русское наименование, инструкции по ремонту разделов
nte240/  nte200/  tr100/   — полные родные каталоги каждой машины
                             (руководства, ремонт, каталог двигателя, чертежи)
cummins/           — каталог двигателя EPC + база знаний Cummins
build/gen_data.js  — генерация data/catalogs.js и data/prices.js из подпапок
build/gen_engine_sup.js   — генерация data/engine_sup.js
build/gen_engine_parts.js — генерация data/engine_parts.js
build/gen_part_docs.js    — генерация data/part_docs.js (документы базы знаний
                     по номеру и инструкции по ремонту разделов)
build/gen_kb.js    — перенос базы знаний из репозитория Cummins_Parts_Book
build/gen_nte240_manual.py  — руководство оператора NTE240 из .docx
build/gen_nte240_service.py — инструкции по ремонту NTE240 из перевода
```

Пересобрать объединённые данные после изменений в подпапках:

```
node build/gen_data.js
node build/gen_engine_sup.js
node build/gen_engine_parts.js
node build/gen_part_docs.js      # после gen_kb.js — он берёт данные из cummins/
```

## Публикация на Vercel

- Framework preset: **Other** (статический сайт, без сборки).
- Build Command: пусто. Output/Root Directory: **корень репозитория** (`/`).
- `index.html` уже в корне — Vercel отдаёт его как главную страницу.
- `vercel.json` задаёт долгий кэш для картинок и проверку актуальности для
  `.js`/`.css`/`.html`.

## Доступ: вход по логину и паролю

Весь сайт закрыт **серверным входом** (Vercel Edge Middleware) — файлы не
отдаются без авторизации. Один вход открывает всё: каталоги, двигатель,
руководства, картинки.

- `middleware.js` — проверяет сессионную cookie на каждом запросе, иначе
  редиректит на `/login.html`.
- `api/login.js` — проверяет логин/пароль (PBKDF2) и срок временных учёток,
  выдаёт подписанную (HMAC) HttpOnly-cookie. `api/logout.js` — выход.
- `auth/accounts.mjs` — учётки (хеши PBKDF2, безопасно хранить в репозитории).
- `auth/token.mjs` — крипто (Web Crypto, без зависимостей).

**Два типа учёток:**
- **Постоянная** (`role: "permanent"`) — без срока (владелец).
- **Временная** (`role: "temporary"`) — с датой `expires`; после неё вход
  отклоняется. Можно завести сколько угодно именных временных логинов.

### Управление логинами

```bash
node build/make_user.mjs set <логин> <пароль> --role permanent --name "Имя"
node build/make_user.mjs set <логин> <пароль> --role temporary --expires 2026-12-31 --name "Подрядчик"
node build/make_user.mjs del  <логин>
node build/make_user.mjs list
node build/make_user.mjs secret     # сгенерировать AUTH_SECRET для Vercel
```
После изменений — закоммитить `auth/accounts.mjs` (Vercel передеплоит).

### AUTH_SECRET (обязательно настроить)

Cookie подписывается секретом. Задайте его в **Vercel → Settings →
Environment Variables → `AUTH_SECRET`** (значение из `make_user.mjs secret`).
Пока переменная не задана, используется резервный секрет из репозитория —
работать будет, но для реальной защиты **обязательно** задайте свой и держите
его в тайне. Смена секрета завершает все активные сессии.

> Клиентский `gate.js` из прежней версии отключён (no-op) — доступ теперь
> полностью на стороне сервера.

## (устар.) Пароль и срок действия

Весь сайт (единое приложение и родные каталоги в подпапках) закрыт одним
паролем и сроком действия (`gate.js`). На одном домене пароль вводится один раз
для всего. Текущий пароль — как в исходных каталогах.
